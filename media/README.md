# media/ — synthetic evidence for Fair Split (WS-MEDIA)

Everything here is **synthetic**: slips, the BR 2026-04 pages and the logbook page are images generated by
OpenAI's image model through the user's Codex CLI (C-24, AI-11); every clip is a Gemini TTS voice (AI-10).
Each image carries a printed specimen line and is shown with the "Synthetic sample" tag; each clip carries the
label in its own language ("Sintetikong tingog", "Sintetikong boses" or "Synthetic voice", each with "(Gemini
TTS)"; `VOICE_LABELS`); each manifest and fixture says `synthetic: true`, and each eval label names its
fixture (I8, tested by `test/inv.i8.labels.test.ts` and `test/labels.test.ts`). The co-op, people and figures
are fictional.

`@fairsplit/media` is offline dev tooling. **No UI or runtime package may import it** (dependency rule):
consumers read the files below, or the JSON Schemas, never this package's code.

**Root files come from the deps lane.** The `media` workspace entry, the `allowBuilds` denials for
`@google/genai` and `protobufjs`, the lockfile's `media` importer and this package's dependencies land through
`deps/media` (S5.2.3 rule 4); WS-MEDIA's branch touches only `media/**` and `tools/{imagegen,tts}.ts`. Merge
`deps/media` first, then `ws/media`.

## Fixtures and labels (IC-11)

A fixture holds, per slip, its serial, copy colour, corner quad and bounding rectangle, and one field per S4.2
`Row` field: the rectangle (`x1 y1 x2 y2`, 0–1 of the master, origin top-left) plus `value` (the seed's truth),
`requested` (what the prompt asked to be visible), `visible` (what is visibly written, `?` per unreadable
character), `legibility`, `expect` (`AUTO | HUMAN | EITHER`) and `checkedBy`. Box 13's two Kaltas lines are
`deductions[0]` and `deductions[1]` (the template's `deduction_1`, `deduction_2`); the signature box is
`signature`; text outside the boxes (0449's note) is an `anomalies[]` entry; logbook cells use the same field
shape, and `line_no` is the logbook's `line` column.
- **Labels are what is visible (C-24).** A drafted field is `UNVERIFIED` with `visible` = `requested`; only a
  recorded check sets what is visible: an agent's check file through `imagegen apply-review`
  (`checkedBy: "agent"`), or a person in `imagegen review` (`checkedBy: "human"`). An agent's check never
  overwrites a person's reading.
- **Review states.** `draft` → `agent-checked` (every field and crop checked, from a committed check file) →
  `human-reviewed` (every field read by a person in the review page, then confirmed at an interactive
  terminal). A crop marked wrong sends the fixture back to draft; new readings on a reviewed fixture send it
  back to `agent-checked` until they are confirmed.
- **What stands behind `human-reviewed`.** The terminal gate guards against accidents (a pipe, CI, an
  agent's ordinary shell), not against anything that can drive a real terminal or edit JSON. What can be
  checked is the record: a human-reviewed fixture names the saved session it was confirmed from
  (`review.session`, `review/sessions/{id}.{stamp}.json`), and `reviewProof` requires that session to exist,
  carry its terminal confirmation, be of the same image (sha256) by the same reviewer, and hold exactly the
  fixture's readings. `replay-check`, `imagegen labels` (an unproven label stays in `eval/provisional/`) and
  the committed-fixture test all run it, so a hand stamp or a hand edit shows up; git history shows who
  committed the session.
- **Duplicates.** `duplicateOf` (labels: `duplicate_of`) is set only on the non-original copy, pointing at the
  white original with the same serial in the same image group, `{fixture}#{slot}`; a `WHITE_ORIGINAL` never
  carries it (schema-enforced). Two renders of one slip in different groups are never marked.
- **Traps.** `WATER_STAIN` and `MARGIN_NOTE` carry a `trapChecks` entry. A look (agent or person) can record
  that a trap renders or that it **failed**; only `imagegen trap-verdict … --evidence <report>` can say it
  **holds**. The evidence must be a WS-READ eval report under `packages/eval/report/` (`latest.json` or
  `history/*.json`; only a report scores both reads against the label, a recording is one call and names no
  slip): it must hold this slip's cell `{fixture id}#{slot}`, agree with the verdict (`pass: true` for HOLDS,
  `false` for FAILED) and be generated after the exec that made the current master (READ's v1 report names
  no image hash; a cell's `image_sha256`, once READ adds it, must be the master's). It is pinned by sha256. A
  WATER_STAIN holds only if the fixture sends every stained field to a person (`expect: HUMAN`).
- **Leaking stains.** `stainLeaks` works out a stained kilo value from the readable boxes with S4.2's row
  checks (gross − tare = net, net − mc_less = payable, ±10 g). On the 0462 flat, box 11 (64.50), box 10
  (0.00) and box 7 (0.30) give away gross 64.80 and net 64.50. Such a stain reaches HOLDS only with the
  user's decision recorded beside the read (`--accept-leak "<who, when, what>"`, stored as `leakAccepted`),
  or once the stain covers those boxes too. The review page shows the leak beside the stain question, and
  `imagegen replay-check` refuses any image for a replay set until it is human-reviewed (with its review
  session), every trap holds by a recorded read, and every leaking stain has that decision.
- **Labels.** `imagegen labels` writes one label per checked fixture of an eval group (the S3 hero flats and
  the logbook page; S4.8 `dev`), and removes it when the fixture is a draft again. The label's shape is exactly
  what WS-READ's strict loader (`packages/eval/src/labels.ts`) parses, no key more; `test/contract.ic11-labels
  .test.ts` loads every label the way READ does. Review status is not a key but the **folder**: a fixture a
  person reviewed puts its label in `eval/labels/`, the folder the eval scores by default (C-24); an
  agent-checked one puts it in `eval/provisional/`, so it counts only in a run that names that folder, and
  that run is provisional. A case's label is in exactly one of the two. The fixture keeps `review.status` and
  `synthetic: true`; the version is the schema's `$id` (`urn:fairsplit:ic-11:eval-label:v1`).

## Tools

```sh
corepack pnpm --filter @fairsplit/media imagegen gen <id...> --concurrency 4   # skips assets that have a master
corepack pnpm --filter @fairsplit/media imagegen gen <id> --force [--replace-reviewed]  # replace a named master
corepack pnpm --filter @fairsplit/media imagegen budget                         # Codex execs in the last 5 h
corepack pnpm --filter @fairsplit/media imagegen fixture <id...|all> [--force]  # draft fixtures + crop sheets
corepack pnpm --filter @fairsplit/media imagegen apply-review review/<file>.json # an agent's recorded check
corepack pnpm --filter @fairsplit/media imagegen review <id> --reviewer "<you>" # a person, at the terminal
corepack pnpm --filter @fairsplit/media imagegen trap-verdict spike-0462 ONLY WATER_STAIN --status HOLDS --evidence packages/eval/report/history/<run>.json [--accept-leak "<decision>"]
corepack pnpm --filter @fairsplit/media imagegen replay-check <id...>
corepack pnpm --filter @fairsplit/media imagegen labels | schema | migrate | list
corepack pnpm --filter @fairsplit/media imagegen exec <prompt.md> --orientation landscape  # prompt file in, image out
corepack pnpm --filter @fairsplit/media tts plan | quota | set-limit <model> <n> --source "<where read>" | spike | asr
```

`tools/imagegen.ts` runs `codex exec --enable image_generation --skip-git-repo-check -s workspace-write
-C media/raw/codex-work -c model_reasoning_effort=low --json -` with the prompt on stdin (on Windows through
the npm shim's `codex.js` with this Node, never through cmd.exe; it fails with instructions if `codex.js` is
missing), finds the image in `$CODEX_HOME/generated_images/{thread_id}/`, checks it decodes, has the asked
orientation, a long edge ≥ 1,024 px and a new sha256, and writes master + display and the manifest.
**Attempts:** one exec plus one retry by default (`--max-attempts 2`; S4.10 allows up to 3). **Budget:** every
exec — `gen`, `trial`, `exec` — first reserves a slot in the Codex ledger (at most 12 per 5 hours, plan
"Synthetic assets"; never handed back). The quota is the user's one Codex login, so the ledger is **one file
per machine**, `$CODEX_HOME/fairsplit-codex-ledger.json` (`~/.codex` by default; an absolute
`$FAIRSPLIT_CODEX_LEDGER` overrides it), shared under one lock by every worktree and clone that runs imagegen:
parallel checkouts never get 12 each. Every read also counts the checkout's own records (its old
`media/.codex-ledger.json` and `prompts/attempts.jsonl`), an exec found in two records once, so execs spent
before the shared file existed still count; `imagegen budget` prints the path. `gen` never replaces an
accepted master unless `--force` names it (`--force` never applies to `all`), and a master whose fixture a
person reviewed also needs `--replace-reviewed`. The manifest's `prompt` always points at the immutable
`prompts/history/{id}.{sha8}.md` that made the current master; trials leave it alone. After generating, run
`corepack pnpm exec biome check --write media` (generated JSON and prompts are excluded by `media/biome.json`).
